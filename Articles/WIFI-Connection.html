كيف يتصل جهازك بشبكة الـ Wi-Fi؟ شرح مبسّط من أول خطوة حتى التشفير

بواسطة : ايهاب ثائر

لو سألت نفسك: "كيف جهازي يعرف الشبكات القريبة ويتصل بها؟" الموضوع في الحقيقة سلسلة خطوات منظمة، تبدأ بالتعارف وتنتهي بالتشفير الكامل للبيانات.

1. اكتشاف الشبكات القريبة

أول ما تفتح الواي فاي على جهازك، يصير حوار بسيط بينه وبين الشبكات المحيطة:

  • جهازك يرسل رسالة اسمها Probe Request، كأنه يسأل: "فيه أحد موجود؟"
  • أي شبكة قريبة ترد برسالة Probe Response: "أنا هنا! اسمي كذا، وأدعم نوع التشفير الفلاني، وهذه إمكانياتي."

2. التوثيق (Authentication)

هذه المرحلة مثل مصافحة البداية(محاولة الاتصال بالشبكة):

  • الجهاز يطلب من الشبكة السماح له بالمحاولة للدخول.
  • الشبكة ترد بالموافقة سواء كان الرمز غلط او صح اذا كانت الشبكة محمية لان هذا التوثيق ما له علاقة بالباسورد، هو فقط إثبات وجود ورغبة في الاتصال، برسائل بسيطة جداً.

3. ربط الجهاز بالشبكة (Association)

بعد المصافحة او الموافقة، الجهاز يقدم نفسه بشكل أوضح:

  • ويذكر نوع التشفير و إمكانياته.
  • الشبكة ترد بالموافقة وتعطيه رقم تعريف داخل الشبكة (AID).

للآن، لا يوجد إنترنت ولا تشفير… لأن المفاتيح السرية لم يتم تبادلها بعد.

4. مرحلة الأمان – 4-Way Handshake

هنا تبدأ الخطوة الأهم: تأكيد أن الجهاز والراوتر يعرفان كلمة السر، وإنشاء مفاتيح التشفير

تتم المصافحة بأربع رسائل:

  1. الراوتر يرسل رقم عشوائي (ANonce) للجهاز.
  2. الجهاز يرد برقم عشوائي (SNonce) + كود تحقق (MIC) يثبت معرفته بكلمة السر.
  3. الراوتر يتحقق ويرسل مفتاح التشفير الجماعي (GTK) + MIC جديد.
  4. الجهاز يرد للتأكيد.

بعد هذه الخطوة، كل البيانات بينك وبين الراوتر تصبح مشفرّة، وأي شخص يحاول التجسس سيرى مجرد بيانات غير مفهومة.

5. ماذا يُرسل في الهواء؟

كل رسالة تُرسل عبر الـ Wi-Fi لها جزئين:

  • Header: بيانات تعريفية عن نوع الرسالة.
  • Payload: المحتوى الفعلي (البيانات).

بعض الرسائل فيها الاثنين، وبعض الرسائل الصغيرة مثل ACK يكون فيها الـ Header فقط.

بعد التشفير، تبدأ البيانات الحقيقية (تصفح، فيديو، محادثات) بالمرور داخل الـ Payload بشكل مشفر.

6. كيف تراقب هذه العملية باستخدام Wireshark؟

إذا كان كرت الـ Wi-Fi لديك يدعم Monitor Mode، يمكنك مشاهدة هذه العملية.

  • wlan.fc.type_subtype == 0x04 → Probe Request
  • wlan.fc.type_subtype == 0x05 → Probe Response
  • wlan.fc.type_subtype == 0x0b → Authentication
  • wlan.fc.type_subtype == 0x00 or 0x01 → Association
  • eapol → Handshake (WPA/WPA2)

الخلاصة

  1. اكتشاف الشبكة (Probe).
  2. التوثيق والربط (Authentication & Association).
  3. تبادل المفاتيح والتشفير (4-Way Handshake).

English Version

If you’ve ever wondered how your device detects nearby networks and connects, the process is actually a series of structured steps, starting with discovery and ending with full data encryption.

1. Discovering Nearby Networks

  • Your device sends a Probe Request, like asking: “Is anyone there?”
  • Any nearby network responds with a Probe Response: “I’m here! This is my name, my encryption type, and my capabilities.”

2. Authentication

  • The device asks the network for permission to attempt connection.
  • The network responds with approval — this step only confirms presence and willingness to connect.

3. Association

  • The device introduces itself more clearly, stating encryption type and capabilities.
  • The network agrees and assigns an Association ID (AID).

4. Security Stage – 4-Way Handshake

  1. The router sends a random number (ANonce) to the device.
  2. The device responds with its own random number (SNonce) plus a MIC proving it knows the password.
  3. The router verifies and sends the Group Temporal Key (GTK) plus a new MIC.
  4. The device confirms.

5. What’s Sent Over the Air?

  • Header: Identifying information about the message type.
  • Payload: The actual data being sent.

6. Monitoring with Wireshark

If your Wi-Fi card supports Monitor Mode, you can watch this process in action.

  • wlan.fc.type_subtype == 0x04 → Probe Request
  • wlan.fc.type_subtype == 0x05 → Probe Response
  • wlan.fc.type_subtype == 0x0b → Authentication
  • wlan.fc.type_subtype == 0x00 or 0x01 → Association
  • eapol → Handshake (WPA/WPA2)
